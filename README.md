# Doctor Prescription & Patient Management System

A single-doctor / small-clinic practice management system built on **Laravel 12**. It lets a physician register patients, record visit/case history, prescribe medications, order tests, and generate printable prescriptions (PDF/DOCX).

## Tech Stack

- **Framework:** Laravel 12 (monolith — server-rendered UI + JSON API in one project)
- **Auth:** session guard (`web`) for the Blade UI, JWT via `php-open-source-saver/jwt-auth` (`api` guard) for the API; roles/permissions via `spatie/laravel-permission`
- **Database:** MySQL
- **Planned (not yet wired up):** Elasticsearch (search), Redis (cache/queue/sessions), DomPDF/PhpWord (document export) — see the doc's build order below

## Requirements

- PHP 8.2+ with the `sodium` extension enabled (required by the JWT library)
- Composer
- MySQL
- Node.js (for the Vite asset pipeline)

## Setup

```bash
composer install
cp .env.example .env
php artisan key:generate
php artisan jwt:secret          # required for the API login

# configure DB credentials in .env, and set SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD
php artisan migrate --seed      # roles, permissions, super admin (+ demo users in local)

npm install
npm run dev   # or: composer run dev
```

`php artisan db:seed --class=AccessSeeder` is safe to re-run after each deploy: it syncs the `Permission` enum to the database and creates missing roles, without overwriting permission changes made in the role admin.

In `local`, the seeder also creates `doctor@example.com` and `assistant@example.com` (password `password`).

## Authentication

| Client | Guard | Login |
|---|---|---|
| Blade UI | `web` (session cookie) | `GET/POST /login`, `POST /logout` |
| API (future Angular / mobile) | `api` (JWT) | `POST /api/v1/auth/login`, `refresh`, `logout`, `GET auth/me` |

Both logins share `LoginRequest` + `AuthenticateAction`: 5 failed attempts per email + IP lock the login for 60 s, and 30 failed attempts from one IP across any emails lock it for 15 min (API: `429` + `Retry-After`). Inactive users cannot log in, and deactivated users lose access on their next request (`active` middleware). Deactivation also bumps `users.token_version` and rotates the remember-me token, so JWTs and sessions issued before it stay revoked if the account is reactivated.

## Roles & permissions

- Permissions are defined in code: `app/Domain/Access/Permission.php`. Authorize by permission (`$user->can('cases.finalize')`, `permission:` middleware, policies), never by role name.
- Roles are data (`spatie/laravel-permission`), edited by a super admin at `/admin/roles` or `/api/v1/roles`. Defaults (spec §8.5) are in `app/Domain/Access/Role.php`.
- `super_admin` passes every check via `Gate::before`; the role itself cannot be edited or deleted, only a super admin can grant it, and the last active super admin cannot be removed.
- All roles live on the `web` guard; JWT requests are checked against the same set.
- Users: `/admin/users` or `/api/v1/users`. Users are deactivated, never deleted.

## Audit log

`App\Domain\Audit\AuditLogger` writes append-only rows to `audit_logs` (user, action, subject, IP, user agent). P1.1 records logins, failed logins, logouts and every user/role change. Never put passwords or clinical text in `properties`.

## API docs

OpenAPI is generated by Scramble: browse `/docs/api` (open in `local`, super admin elsewhere) or run `php artisan scramble:export`. CI uploads `openapi.json` as an artifact.

## Tests

```bash
php artisan test
```

Tests use SQLite in memory (`pdo_sqlite` required). Without it, point them at a scratch MySQL database:

```bash
DB_CONNECTION=mysql DB_DATABASE=doctor_prescription_app_test php artisan test
```
